## HIAI-UI-T02 — round-3

### Production

`src/components/ui/popover/popover.svelte` is again a thin bits-ui Root wrapper. **No** document `keydown` listener, **no** `querySelector` focus of an arbitrary open trigger.

### Test harness (jsdom only)

- `HarnessKeyboardEvent` in `src/__tests__/setup.ts`: bits-ui does `new KeyboardEvent(e.type, e)`; rebuild init with `key`/`code` so the clone is not already canceled. Does not change shipped keyboard ownership.
- `activateTrigger`: focus then click so FocusScope records the trigger.
- `pressEscape`: cancelable `keydown` on `document` (where bits-ui EscapeLayer listens).

### Regressions

- Single: Escape closes; focus returns to **that** trigger.
- Nested: Escape closes **inner only**; outer stays open; focus returns to inner trigger.
- Two siblings (`interactOutsideBehavior="ignore"` so both can stay open): Escape closes **top (B) only**; A stays open; focus stays in remaining layer A (content trap), not B’s trigger.
- `onEscapeKeydown` `preventDefault`: stays open.

### Dist consumer

- `resolvePackageExport` walks `package.json` `exports` (`svelte` → `default` → string) and `import()`s those files.
- Vitest plugin `hiai-ui-package-exports` resolves `@hiai-gg/hiai-ui/...` through the same map (not a prefix alias to `dist/`).
- `DistConsumerFixture` still renders Popover/Command/Combobox from those specifiers.

jsdom is **not** browser coverage. No `test:e2e`. Runtime/visual/LAN HTTP not claimed. Lightpanda not used.
